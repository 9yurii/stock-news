# 📈 주식 뉴스 해설 아카이브

하루 3번 들어오는 뉴스를 **왕초보용 7단계 해설**로 정리하고, 날짜별로 쌓아 나중에 찾아볼 수 있게 하는 프로그램입니다.

- **웹사이트**: GitHub Pages (HTML/CSS/JS, 정적)
- **데이터베이스**: Supabase (Postgres)
- **해설 작성**: Claude Code의 `/news` 명령
- 파이썬 외부 라이브러리 0개 — `pip install` 필요 없음

---

## 권한 구조

| | 누구나 | 허용된 계정 |
|---|---|---|
| 해설 읽기 | ✅ | ✅ |
| 뉴스 입력·수정·삭제 | ❌ | ✅ |

단톡방에 사이트 링크를 공유하면 상대방은 **로그인 없이 바로 읽을 수 있습니다.**
쓰기는 Supabase의 `allowed_writers` 목록에 등록된 이메일(현재 `iam9yuri@gmail.com`)로 로그인했을 때만 가능하며, 이는 데이터베이스 정책(RLS)으로 강제됩니다. 다른 사람이 회원가입해도 읽기만 됩니다.

## 최초 1회 준비

### 0. Supabase 주소 설정 (가입 메일 링크가 제대로 열리도록)

[Supabase 대시보드](https://supabase.com/dashboard/project/uvuroizlboirzehiagwb/auth/url-configuration) → Authentication → URL Configuration 에서

- **Site URL**: `https://9yurii.github.io/stock-news/`
- **Redirect URLs**에 같은 주소 추가

이걸 안 하면 가입 확인 메일의 링크가 `localhost:3000` 으로 가서 열리지 않습니다.

### 1. 웹사이트에서 계정 만들기

사이트 → **로그인** → 이메일·비밀번호 입력 → **가입하기** → 메일로 온 확인 링크 클릭.

쓰기 권한은 `iam9yuri@gmail.com` 에만 있으므로, 이 이메일로 가입해야 뉴스를 입력할 수 있습니다.

### 2. `.env` 파일 만들기

`.env.example` 을 복사해 `.env` 로 이름을 바꾸고 위에서 만든 정보를 넣습니다.

```
SUPABASE_EMAIL=iam9yuri@gmail.com
SUPABASE_PASSWORD=비밀번호
SITE_URL=https://9yurii.github.io/stock-news
```

`.env` 는 git에 올라가지 않습니다.

### 3. 확인

```bash
python -m stock_manager.cli init
```
`로그인 계정: ... (쓰기 가능)` 이 나오면 준비 끝입니다.

## 매일 쓰는 법

### 방법 A — 웹에서 넣고, Claude Code로 해설

1. 사이트 → **뉴스 입력** → 날짜·시간대·제목·주소·본문 저장 (= "해설 대기")
2. Claude Code에서 `/news` 실행 → 대기 중인 뉴스를 순서대로 해설하고 저장
3. 사이트에서 바로 읽고, **단톡방용 복사** 버튼으로 공유

### 방법 B — Claude Code에 바로 붙여넣기

```
/news            ← 대기 중인 뉴스 전부 처리
/news 3          ← 3번 뉴스만 처리
/news <기사 본문 + URL 붙여넣기>   ← 웹 입력 없이 바로 해설
/news 2026-07-25 <기사 본문>      ← 지난 날짜로 저장
```

지난 며칠치를 몰아서 올려도 됩니다. 웹 입력 폼의 **날짜**를 기사 날짜로 바꾸면 목록에서 그 날짜 자리에 정리됩니다.

### 방법 C — 카카오톡 대화방에서 가져오기

카카오톡은 대화방을 밖에서 읽어가는 API가 없습니다. 대신 카톡의 **대화 내보내기** 파일을 읽어들입니다.

**내보내는 법**

| 기기 | 경로 |
|---|---|
| PC | 대화방 → 오른쪽 위 메뉴 → 대화 내용 → 대화 내용 저장 |
| 안드로이드 | 대화방 → 메뉴(≡) → 설정(⚙) → 대화 내용 내보내기 → 텍스트만 보내기 |
| 아이폰 | 대화방 → 메뉴(≡) → 설정(⚙) → 대화 내용 내보내기 → 텍스트 파일로 저장 |

**가져오기**

```bash
# 먼저 무엇이 들어갈지만 확인 (저장 안 함)
python -m stock_manager.cli import-kakao "대화.txt" --dry-run

# 실제로 가져오기
python -m stock_manager.cli import-kakao "대화.txt"

# 특정 사람이 올린 것만, 특정 기간만
python -m stock_manager.cli import-kakao "대화.txt" --sender 박영희 --date-from 2026-07-20
```

### 사진까지 가져오려면

**txt 파일 하나만으로는 사진을 가져올 수 없습니다.** 내보내기 txt에는 사진 원본이 없고 `사진` / `사진 3장` 같은 자리표시 글자만 남기 때문입니다. 사진까지 옮기려면 **txt와 이미지 파일이 함께 있는 폴더(또는 zip)** 를 주면 됩니다.

**PC 카카오톡** — "모든 파일 보내기"는 **PC에 없습니다.** 두 가지를 따로 챙기세요.

1. 대화 저장: 대화방 → 오른쪽 위 `≡` → **대화 내용** → **대화 내용 저장** → txt 저장
2. 사진 저장: 대화방 오른쪽 위 `≡` → **사진/동영상** (서랍) → 전체 선택 → **저장**
3. txt와 사진을 **같은 폴더**에 넣고 그 폴더 경로를 지정

**안드로이드** — 대화방 → `≡` → 톱니바퀴 `⚙` → **대화 내용 내보내기** → **"모든 메시지 내보내기(사진·동영상 포함)"** 선택 → 나온 zip 파일을 PC로 옮기기

**아이폰** — 대화방 → `≡` → `⚙` → **대화 내용 내보내기** → **"모든 파일 보내기"** → 파일에 저장 → PC로 옮기기

> 카카오톡 버전에 따라 메뉴 이름이 조금 다를 수 있고, 사진 포함 내보내기가 아예 없는 버전도 있습니다. 그럴 땐 PC 방식(사진 서랍에서 저장)이 가장 확실합니다.

```bash
# 폴더를 통째로 (txt + 사진)
python -m stock_manager.cli import-kakao "C:\내보내기폴더" --dry-run

# zip 그대로 줘도 됩니다
python -m stock_manager.cli import-kakao "대화.zip"
```

사진은 파일 이름의 시각을 읽어 **시간이 가까운 뉴스에 자동으로 붙습니다.** 짝이 없는 사진은 "사진 뉴스"로 따로 한 건이 됩니다. `/news` 는 사진을 직접 열어보고 그 안의 기사 내용까지 읽어 해설합니다.

("이 사진 보세요…" 처럼 사진이라는 낱말이 들어간 **진짜 메시지는 정상적으로 가져옵니다.** 자리표시 글자와 정확히 일치할 때만 걸러냅니다.)

### 전달해 주는 사람의 코멘트도 함께

뉴스만이 아니라, 그 뉴스를 전달해 준 사람의 설명과 방 사람들의 반응도 함께 담깁니다.

- 뉴스를 올린 사람이 **바로 이어서** 쓴 설명 → 기사 본문에 합쳐집니다
- 다른 사람들의 반응, 뒤이은 대화 → **"단톡방에서 오간 이야기"** 로 따로 보관되어 웹사이트에 그대로 보입니다
- 해설을 쓸 때 이 대화는 **참고용**으로만 씁니다. ② 팩트 정리에는 들어가지 않고, 언급할 때는 "이 뉴스를 나눈 분들 사이에서는 ○○라는 이야기가 나왔습니다"처럼 출처를 밝힙니다
- 대화는 빼고 기사만 원하면 `--no-comments`

**동작 방식**

- 링크가 들어간 메시지, 그리고 링크가 없어도 120자 이상인 긴 메시지를 뉴스로 봅니다 (`--min-length`로 조절).
- 같은 사람이 이어서 보낸 코멘트는 한 건으로 묶고, **각자 링크가 있으면 별개 뉴스로** 나눕니다.
- **이미 정리한 뉴스는 자동으로 빠집니다.** 카톡 내보내기는 늘 대화 전체를 담고 있어서, 며칠 뒤 다시 내보내도 새로 올라온 것만 들어갑니다. 판정은 주소 기준이며, `utm_source` 같은 추적 꼬리표나 `www.`, 끝 슬래시 차이는 무시하므로 같은 기사를 다시 공유해도 한 건으로 봅니다.

## 해설 구조

모든 해설은 아래 7단계를 그대로 따릅니다.

| | 섹션 | 내용 |
|---|---|---|
| ① | 30초 요약 | 중학생도 아는 한 문장 + 성격(호재/악재/중립/해석이 갈림) |
| ② | 팩트 정리 | 숫자와 사실만, 해석 금지 |
| ③ | 시장의 속마음 | 표면적 이유 vs 진짜 이유, 일상 비유 |
| ④ | 찬반 시각 | 낙관론 / 비관론 / 갈리는 핵심 |
| ⑤ | 체크리스트 | 오늘 밤 → 내일 → 이번 주 → 이번 달 |
| ⑥ | 상황별 관점 | 현금 / 보유 / 신규 (투자권유 아님) |
| ⑦ | 용어 복습 | 꼭 알아야 할 용어 3개 |

저장할 때 자동으로 검사합니다. 7개 섹션이 빠지거나, ⑥에 "사세요/파세요" 같은 권유 표현이 들어가거나, "판단과 책임은 본인의 몫" 문구가 없으면 **저장이 거부**되고 다시 쓰게 됩니다.

## 터미널에서 쓰기 (선택)

```bash
python -m stock_manager.cli list                    # 목록
python -m stock_manager.cli show 3                  # 3번 리포트 보기
python -m stock_manager.cli show 3 --kakao          # 단톡방용 평문
python -m stock_manager.cli search 반도체            # 검색
python -m stock_manager.cli terms                   # 용어 사전
python -m stock_manager.cli tickers                 # 종목 집계
python -m stock_manager.cli tickers --name 삼성전자   # 종목 타임라인
python -m stock_manager.cli export 3 --out 리포트.md
python -m stock_manager.cli whoami                  # 내 권한 확인
```

## 개발

```bash
python -m stock_manager.web     # docs/ 로컬 미리보기 (미리보기_실행.bat 더블클릭도 가능)
```

`docs/` 폴더가 GitHub Pages로 그대로 배포됩니다. `main` 브랜치에 push하면 몇 분 안에 반영됩니다.

| 파일 | 역할 |
|---|---|
| `docs/index.html` | 페이지 뼈대 |
| `docs/style.css` | 스타일 (라이트/다크 모드 자동) |
| `docs/app.js` | 화면·라우팅·Supabase 연동 |
| `docs/config.js` | Supabase 주소와 공개 키 |
| `stock_manager/report.py` | 7단계 형식 정의와 검증 규칙 |
| `stock_manager/db.py` | Supabase 데이터 접근 |
| `.claude/commands/news.md` | `/news` 명령 (해설 작성 지침) |

## 앞으로

종목별 뉴스가 쌓이면(`종목` 탭), 그 기록을 바탕으로 종목 단위 분석 기능을 얹을 수 있도록 `tickers` 테이블을 미리 만들어 두었습니다.

다만 매수·매도 적정가는 누구도 정확히 맞출 수 없는 영역입니다. **정답을 내려주는 도구**가 아니라 **근거와 시나리오를 정리해 판단을 돕는 도구** 방향으로 확장하는 것을 권합니다.
